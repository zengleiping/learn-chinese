# 生詞練習台－連連看／圈出來（GitHub Pages 版）

給一對一線上華語課用的連連看／圈出來出題工具。老師出題、切換題目、公布答案；學生打開一個連結就能跟著畫面走，老師開放作答時可以直接點選。

## 兩種模式

**本機單人模式（完全不用設定，馬上能用）**
把 `index.html` 直接用瀏覽器打開，或上架到 GitHub Pages 之後打開網址，就可以自己編輯題目、自己練習、簡報模式分享畫面。所有題目存在瀏覽器裡（localStorage）。這個模式跟下面的 Firebase 設定完全無關，就算不做任何設定也不會壞掉。

**房間連線模式（需要花幾分鐘做一次 Firebase 設定）**
老師按「🔗 開新房間」，系統會產生一個像 `8823` 這樣的 4 位數房間代碼，並自動組出一個學生專用連結（例如 `https://你的網址/?room=8823&role=student`）。把這個連結貼給學生（貼在視訊軟體聊天室即可），學生點開就自動加入房間，畫面會跟著老師走；老師打開「開放學生作答」之後，學生點選的結果老師端會立刻同步看到。這個模式需要一個免費的 Firebase 專案來當「即時同步」的資料庫，設定步驟在下面。

---

## Step 1：先上架到 GitHub Pages

1. 到 [github.com](https://github.com) 建立一個新的 repository（公開 public 即可，完全免費）。
2. 把這三個檔案上傳到 repository 的最上層（不要放進資料夾裡）：`index.html`、`rules.json`、`README.md`。GitHub 網頁上就有「Add file → Upload files」，用拖曳的就可以，不需要用指令。
3. 進入這個 repository 的 **Settings**，左側選單找到 **Pages**。
4. 在「Build and deployment」底下，「Source」選 **Deploy from a branch**，Branch 選 `main`（或你的預設分支）、資料夾選 `/(root)`，按 **Save**。
5. 等 1～2 分鐘，重新整理這個設定頁面，上面會出現一個網址，通常長得像 `https://你的帳號.github.io/repository名稱/`。這就是要給學生的網址（之後 `?room=` 的房間連結也會是這個網址加上參數）。

> 做完這一步，本機單人模式就已經可以用了。房間連線模式還需要下面的 Firebase 設定。

---

## Step 2：設定 Firebase（讓「開新房間」可以真正即時同步）

不需要信用卡，免費方案（Spark 方案）就完全夠用。

1. 到 [Firebase 主控台](https://console.firebase.google.com)，登入你的 Google 帳號，按「新增專案」，取個名字（例如「hanyu-practice」），一路下一步建立完成。
2. 專案總覽頁面，按網頁圖示（`</>`）「新增應用程式」，取個暱稱（隨便填），**不用**勾選 Firebase Hosting，按註冊。畫面會顯示一段 `firebaseConfig = {...}` 的設定值，先別關掉這個畫面。
3. 打開你上傳到 GitHub 的 `index.html`（用 GitHub 網頁上的鉛筆圖示編輯，或下載回電腦編輯都可以），找到最上面這一段：
   ```js
   window.FIREBASE_CONFIG = {
     apiKey: "貼上你的 apiKey",
     authDomain: "貼上你的 authDomain",
     databaseURL: "貼上你的 databaseURL",
     projectId: "貼上你的 projectId",
     storageBucket: "貼上你的 storageBucket",
     messagingSenderId: "貼上你的 messagingSenderId",
     appId: "貼上你的 appId"
   };
   ```
   把裡面每一個值換成 Firebase 給你的那一串（`apiKey`、`authDomain`……七個值一一對應貼上），存檔後重新上傳覆蓋 GitHub 上的 `index.html`。
4. 回到 Firebase 主控台左側選單，找到 **Realtime Database**（不是 Cloud Firestore，是 Realtime Database），按「建立資料庫」。地區選離台灣近的（例如新加坡 asia-southeast1），安全性規則先選「測試模式」也沒關係，等一下會換成正式規則。
5. 建好之後，上面會有「規則」（Rules）分頁，把附上的 `rules.json` 裡的內容整個貼進去，取代原本的內容，按「發布」。這組規則的意思是：只有「已登入」的使用者可以讀寫房間資料，比完全公開安全一些，但學生端不需要輸入任何帳號密碼（下一步會說明）。
6. 左側選單找到 **Authentication**（新版介面可能歸類在「Build」分類底下，不同版本位置略有不同，找不到可以用主控台上方的搜尋）。點進去按「開始使用」，在「Sign-in method」分頁裡找到 **匿名（Anonymous）**，把它啟用。這一步是讓老師和學生的瀏覽器可以「悄悄登入」，完全不會出現任何登入畫面或要求密碼。

做完這 6 步，重新整理你的 GitHub Pages 網址，畫面最上面的橘色提示條應該會消失，「🔗 開新房間」就可以正常運作了。

## 上課怎麼用（對照你原本想要的功能）

- **開新房間 / 房間代碼**：老師端按「🔗 開新房間」，會自動產生像 `8823` 的短碼，並跳出視窗顯示可以直接複製的學生連結（`?room=8823` 的形式），貼給學生就好，學生不用輸入代碼、不用登入、不用安裝任何東西。
- **老師（主控端）權限**：房間開好之後，老師可以隨時在左側切換題目、按「＋新增題目」編輯內容、按「🔄重新開始」清空這一題的作答紀錄、按「公布答案」公布，也可以用右上角的開關決定「開放學生作答」或先關閉（例如講解的時候先不讓學生亂點）。
- **學生（參與端）權限**：學生畫面完全跟著老師換題目，在老師還沒開放作答前，畫面會顯示「等待老師開放作答」，開放之後才能點選連連看／圈出來的選項；學生看不到、也不能碰左側題目清單或編輯功能。
- **即時同步的資料**：目前是哪一題（`currentSetId`）、已經連上的配對線、目前圈選了哪個答案、有沒有公布答案（`progress`），都是透過 Firebase 即時同步；學生端點一下，老師端幾乎立刻就會看到（畫面上也會跳出「🎉 學生剛剛配對成功！」或「✏️ 學生更新了作答」的提示）。
- **滑鼠游標軌跡／搶答提示（進階，你的訊息裡列為可選）**：這個版本沒有做逐格同步滑鼠位置或「誰先答對」的排名功能——一對一課堂通常只有一位學生，「搶答」的意義不大，而老師端已經會即時跳出「學生剛答對了／學生更新了作答」的提示，已經能達到「知道學生在做什麼」的效果。如果之後真的想要游標同步，可以再另外加，只是會讓程式複雜不少，先讓核心的房間／同步功能穩定運作。

## 免費額度夠用嗎？

Firebase 免費方案（Spark）：1GB 資料庫儲存空間、同時 100 個連線、每月 10GB 流量。一對一家教這種用量（隨時最多 2 個人連線、資料只有文字題目和選取狀態）非常小，免費額度用不完，也不需要綁信用卡。

## 安全性小提醒

房間代碼只有 4 碼，設計上是「知道連結就能加入」，不是帳密等級的保護，這樣才能讓學生不用登入就能用。因為代碼是老師開房間時隨機產生、只在那堂課用，加上安全規則已經擋掉完全沒登入的人，對一對一家教這種低風險場景是足夠的；但不建議把房間連結公開分享到公開社群或轉發給不相關的人。

## 疑難排解

- 畫面最上面出現橘色提示「還沒有設定 Firebase」：代表 Step 2 的 `FIREBASE_CONFIG` 還沒換成你自己的值，本機單人練習不受影響，但按「開新房間」不會有反應。
- 按「開新房間」跳出「⚠️ 連線功能載入失敗，請檢查網路連線後再試一次」：`FIREBASE_CONFIG` 已經填了，但瀏覽器連不到 Firebase 服務——檢查網路，或確認學校網路沒有擋 `gstatic.com` / `firebaseio.com` 這類網域。
- 學生畫面停在「無法連上連線服務」：跟上面同一個原因，通常是網路問題；也可能是連結裡的房間代碼被打錯或房間已經結束。
- 學生畫面顯示「找不到這個房間」：房間代碼錯誤，或老師已經整堂課結束、重新整理過頁面。請老師重新按一次「🔗 開新房間」，複製新的連結給學生。

## 檔案清單

- `index.html`：主程式，上傳到 GitHub Pages 的就是這一個檔案。
- `rules.json`：Firebase Realtime Database 的安全規則，貼到 Firebase 主控台的「規則」分頁用。
- `README.md`：就是這份說明。
